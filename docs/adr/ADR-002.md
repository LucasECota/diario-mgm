# ADR-002 — Estilo arquitetural: monolito modular em camadas com API REST

| Campo | Valor |
| --- | --- |
| Status | Aceito |
| Data | 15/11/2026 |
| Responsável | Lucas Emanuel Cota Carneiro |
| Cenários e regras relacionados | C02, C03, C05, RN01 a RN07 |

## Contexto

Uma pessoa constrói e opera o sistema em poucas semanas, para uma escola com cerca de 20 professores usando ao mesmo tempo (C03). As regras que mudam precisam ficar isoladas (C02), e o backup e a recuperação precisam ser simples (C05).

## Alternativas consideradas

| Alternativa | Vantagens neste sistema | Desvantagens neste sistema |
| --- | --- | --- |
| Monolito modular em camadas (apresentação, aplicação, domínio, dados) | Uma única implantação e um único banco (backup simples, C05); módulos separam os segredos (C02); suficiente para 20 usuários simultâneos | As camadas dependem de disciplina para não se misturarem; escala só verticalmente |
| Portas e adaptadores (hexagonal) | Domínio totalmente isolado; banco e PDF trocáveis; testes de domínio sem infraestrutura | Mais interfaces e código de ligação para uma pessoa; benefício maior do que o necessário |
| Microsserviços | Implantação e escala independentes por módulo | Rede, dados distribuídos e implantação muito mais caros; nenhum cenário exige |

## Decisão

Um back-end monolítico dividido em módulos de negócio (cadastro, frequência, avaliação, alocação, histórico e auditoria, documentos e acesso), cada um em camadas (rotas, serviços de aplicação, domínio e repositórios). O front-end React é uma aplicação de página única que fala com o back-end por API REST com JSON.

### Consequências

| O que melhora | O que piora (trade-off) | O que fica mais difícil de mudar depois |
| --- | --- | --- |
| Simplicidade de implantação, backup e depuração; fronteiras claras entre módulos | Sem escala independente por módulo; um defeito grave pode derrubar o sistema todo | Dividir em serviços separados (exigiria extrair módulos e separar o banco) |

## Como verificar

As regras de dependência (seção 6 do documento de arquitetura) são conferidas na revisão de código e por testes automatizados (`backend/tests/arquitetura`) que falham se o domínio importar Express, Knex, pg ou pdfmake, ou se um módulo importar outro fora das dependências permitidas; C03 é medido na Etapa 3.

# ADR-001 — Tecnologia e reúso: TypeScript, Node.js/Express, React/Vite, PostgreSQL com Knex

| Campo | Valor |
| --- | --- |
| Status | Aceito |
| Data | 15/11/2026 |

| Cenários e regras relacionados | C02, C03, C05, RN06, RN07 |

## Contexto

O grupo tem uma pessoa e poucas semanas. Ela já domina Node.js, React e PostgreSQL, então a stack precisa reduzir risco de integração (R04). As regras que a cliente disse que mudam (nota mínima, fórmula da média) pedem código fácil de alterar (C02). O histórico completo (RN06 e RN07) pede integridade relacional. O boletim e o histórico precisam sair em PDF (H05, H07).

## Alternativas consideradas

| Alternativa | Vantagens neste sistema | Desvantagens neste sistema |
| --- | --- | --- |
| TypeScript com Node.js/Express, React (Vite) e PostgreSQL | Uma linguagem nos dois lados; tipos protegem as regras de negócio; stack que o Lucas já domina; PostgreSQL garante integridade e transações | Configuração inicial de build e de tipos; duas aplicações (API e interface) no mesmo repositório |
| Java com Spring Boot e interface web renderizada no servidor | Framework completo, forte tipagem e bom suporte a testes | Curva de aprendizado e mais código de configuração; o Lucas não domina; atrasaria o esqueleto |
| Python com Django (monolito com templates) | Painel administrativo, ORM e autenticação prontos; rápido para cadastros | Pouca familiaridade; o ORM esconde o SQL de auditoria; mistura regras e visualização no framework |

## Decisão

TypeScript no back-end e no front-end; Node.js 24 LTS com Express; React com Vite; PostgreSQL 18 acessado com Knex (migrations versionadas) e pg; pdfmake para PDF; Jest e Supertest para testes; GitHub Actions para CI. Monorepo com as pastas `backend` e `frontend`.

### Consequências

| O que melhora | O que piora (trade-off) | O que fica mais difícil de mudar depois |
| --- | --- | --- |
| Produtividade (tecnologias já dominadas); tipos ajudam a proteger as regras; migrations versionam o esquema do histórico; SQL explícito para a auditoria | Dependência de muitas bibliotecas do ecossistema npm e de suas atualizações; mais configuração inicial por causa do TypeScript | A escolha de PostgreSQL (recursos de transação e permissão usados na auditoria) e do Knex, que ficam atrás da camada de dados |

## Como verificar

O esqueleto executa o fluxo mínimo (interface, API e banco) e o pipeline roda build e testes a cada pull request; o cenário C02 é verificado na Etapa 3, com a mudança escolhida.
